# session_notes/

Historical notes from **significant** development sessions: architectural reasoning, major
implementation, difficult debugging, deployment discoveries, performance findings,
important experiments, major refactors.

Not for trivial interactions. Not for current state (that is `../status_update.md`).

## Naming

`YYYY-MM-DD-short-topic.md`, e.g. `2026-10-07-repository-skeleton.md`.

## Suggested structure

```
# <Topic>
Date: / Agent or author:
## Goal
## What was done
## Findings / reasoning worth keeping
## Open questions
## Links (ADRs, files, commits)
```
