# Project vision

## สิ่งที่โปรเจกต์นี้เป็น

mini-agent คือ agent ขนาดเล็กที่ให้ LLM ทำงานจริงได้ โดยตัวระบบแปลงข้อความที่โมเดลตอบให้เป็น
action ส่งผลลัพธ์กลับไปให้โมเดล แล้ววนจนงานเสร็จ เป้าหมายคือ **อ่านจบได้ทั้งระบบ** — ทุกไฟล์สั้นพอที่
คนอ่านไล่บรรทัดเดียวจบ ไม่ซ่อน loop ไว้หลัง framework

## หลักที่ยึด

1. **สัญญาของแต่ละส่วนชัดเจน** — `call_llm` คืน dict เสมอไม่ throw, `sandbox.run` คืน
   `{stdout, stderr, exit_code, timed_out}`, tool คืน string ที่เป็น observation
   เปลี่ยนข้างในได้อิสระตราบใดที่สัญญาไม่เปลี่ยน (เช่น เปลี่ยน sandbox เป็น Docker ทีหลัง)
2. **ตั้งค่าได้โดยไม่แก้โค้ด** — โมเดล, ขอบเขต, เครื่องมือที่อนุญาต, prompt, ลำดับ step อยู่ใน yaml
3. **ข้อผิดพลาดคือ feedback ไม่ใช่ crash** — action ผิดรูป, tool ที่ไม่มี, path นอกขอบเขต, การถูกปฏิเสธ
   ทั้งหมดกลายเป็น observation ให้โมเดลแก้เอง
4. **กฎต้องบังคับได้จริง ไม่ใช่แค่เขียนใน prompt** — การทำซ้ำ, งบ action, การขออนุญาต ถูกบังคับที่ engine
5. **ตรวจสอบย้อนหลังได้** — หนึ่ง session หนึ่งโฟลเดอร์ พร้อม transcript และไฟล์ที่เกิดขึ้นจริง
6. **ความลับอยู่ที่เดียว** — API key อยู่ใน `.env` เท่านั้น ไม่อยู่ในโค้ด ไม่ขึ้น GitHub ไม่ลง log

## ขอบเขต

**ครอบคลุม** — งานที่ทำได้ในโฟลเดอร์เดียว: สร้างและแก้ไฟล์ข้อความ (โค้ด, html, csv, md),
รันสคริปต์ Python เพื่อคำนวณหรือตรวจงานของตัวเอง, ดึงข้อมูลจากเว็บสาธารณะ
งานหนึ่งครั้งจบใน session เดียว มีงบ action จำกัด และมีคนคอยรับช่วงเมื่อ agent ไปต่อไม่ได้

**ไม่ครอบคลุม** — งานที่ต้องจำข้ามวัน, งานที่ต้องใช้ agent หลายตัวพร้อมกัน,
การแก้ไฟล์นอกโฟลเดอร์ของ session, และการทำงานอัตโนมัติเต็มรูปแบบโดยไม่มีคนดู

**ความปลอดภัย** — ขอบเขตที่บังคับได้จริงคือ path ของเครื่องมือจัดการไฟล์ (อยู่ใน workspace เท่านั้น),
ปลายทางของ `http_get` (เฉพาะ public address), และ permission gate ที่ถามคนก่อนรันเครื่องมือที่ตั้งไว้
สิ่งที่ยัง**ไม่**เป็นขอบเขต: โค้ดที่รันผ่าน `run_python` เข้าถึงเครื่องได้เท่าที่ผู้ใช้เข้าถึงได้ —
isolation จริงต้องใช้ container ซึ่งอยู่ในทิศทางข้างล่าง ระหว่างนี้ใช้ permission gate แทน

**ข้อจำกัดที่ยอมรับ** — ตัวตรวจผลงานเป็น LLM จึงไม่ deterministic, ไม่มีการย่อประวัติสนทนา
จึงมีเพดานความยาวของงานหนึ่งชิ้น, และผูกกับ provider เดียว (Groq) เพื่อให้อ่านง่าย

## ทิศทาง

- **ตอนนี้:** agent ทำงานในโฟลเดอร์เดียว มีเครื่องมือจัดการไฟล์ รัน Python และดึงเว็บ
  มี reviewer แยกตัดสินผลงาน และส่งต่อให้คนเมื่อไปต่อไม่ได้
- **กำลังทำ (สัปดาห์ 2):** เครื่องมือค้นเว็บ, ทะเบียนเครื่องมือ + permission เป็น JSON,
  interface แบบ CLI, และ trace ที่ตรวจได้ว่า agent ใช้เครื่องมืออะไรไปบ้าง
- **ต่อไป:** ตัวตรวจแบบ deterministic (เช่น รัน test ของผู้ใช้) แทนที่จะพึ่ง LLM อย่างเดียว,
  isolation จริงของ `run_python` (Docker), การย่อประวัติสนทนาสำหรับงานยาว

ความเรียบง่ายคือคุณสมบัติของโปรเจกต์นี้ ไม่ใช่ข้อจำกัดชั่วคราว — สิ่งที่เพิ่มเข้ามาต้องคุ้มกับ
บรรทัดที่เพิ่มขึ้น ไม่เช่นนั้นไม่เพิ่ม
